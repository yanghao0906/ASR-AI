## 1. 项目概述

### 1.1 背景与目标

做一个类似小爱音箱的**最简可用**语音助手：

- **完全离线运行**，不接入任何大模型语义解析服务；
- 用户对网页说话，系统将语音识别为文字后，匹配到用户预先配置的指令并**执行对应的动作**（一期为 HTTP 操作，如调用智能家居接口）；
- **相似说法归一**："打开空调"、"开空调"、"空调开启"等不同说法命中同一条指令；
- **参数指令严格区分**："温度调到 26 度"、"温度高一点"、"温度调低"是三种不同语义，各自提取参数、互不误命中。

### 1.2 产品定义（一句话）

> 浏览器喊话 → 后端离线识别 → 规则+关键词权重匹配指令 → 执行用户配置的 HTTP 动作 → 网页展示结果。

### 1.3 设计原则

1. **离线优先**：ASR、匹配全部本地推理，无网络依赖（HTTP 动作本身除外）。
2. **无大模型**：语义理解 = 规则槽位匹配 + 关键词权重打分，纯 Java 实现，零额外模型依赖。
3. **规则优先于关键词**：凡带参数的指令必须走规则，关键词只用于无参数的开/关类指令（防止"高一点"与"调低"这类字面相近、语义相反的说法被误归一）。
4. **配置文件是唯一事实源**：指令、动作、系统参数全部以 YAML 文件为准，手改即热加载生效。
5. **一期做薄**：只做核心链路，管理界面、执行历史等全部后移（见第 10 节）。

## 3. 总体架构

### 3.1 链路图

```
┌────────────────────────── 浏览器（Vite 前端） ──────────────────────────┐
│  麦克风按钮 → getUserMedia 采音 → 前端静音检测自动停 → 编码 WAV 上传      │
│  展示：识别文本 / 命中指令 / 槽位 / 执行结果 / 未命中候选                │
└───────────────────────────────┬──────────────────────────────────────┘
                        POST /api/voice/command (audio/wav)
                                ▼
┌────────────────────────── Java 后端（常驻） ───────────────────────────┐
│  ① WAV 解码（16kHz 单声道 PCM）                                        │
│  ② 离线 ASR（Vosk + vosk-model-small-cn-0.22）→ 文本                   │
│  ③ 文本归一化（去空白/标点/语气词、中文数字→阿拉伯数字）                │
│  ④ 意图匹配引擎                                                        │
│     ├ 第一级：规则槽位（各指令的 regex，配置顺序=优先级）               │
│     └ 第二级：关键词权重打分（仅无参数指令）                            │
│  ⑤ 动作执行器（ActionHandler 工厂按 type 分发，一期内置 HTTP Handler）  │
│  ⑥ 配置管理（commands/actions/settings YAML 读写 + 热加载）            │
└───────────────────────────────┬──────────────────────────────────────┘
                                ▼
                     用户配置的目标系统（智能家居网关等）
```

后端空闲时除配置 mtime 轮询外无任何后台任务，CPU 占用约等于 0；Vosk 模型启动时加载、常驻内存，加载完成后预热一次解码（消除首条懒加载延迟）。

### 3.2 关键技术决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 前端直接采集 16kHz PCM 并编码 WAV 上传，不用 MediaRecorder(webm/opus) | 避免 Java 侧引入 opus/ffmpeg 解码依赖，`javax.sound.sampled` 原生读 WAV |
| D2 | 两级匹配：规则槽位优先，关键词权重只兜底无参数指令 | 满足"归一"与"严格区分"并存的核心诉求（见 1.3 原则 3） |
| D3 | 配置文件为唯一事实源，手改 YAML + mtime 轮询热加载 | 一期不做数据库与管理界面，保持简单 |
| D4 | 一体化接口 `POST /api/voice/command`，一次调用返回全链路结果 | 前端一次调用拿到识别/匹配/执行全部信息 |
| D5 | 后端托管前端构建产物，单进程部署 | 一个 jar + 一个配置目录 + 模型目录即可运行，符合跨平台目标 |
| D6 | 动作执行层采用工厂模式：`ActionHandler` 接口 + 工厂按 `actions[].type` 分发 | 新增动作类型只需新增 Handler 实现类，匹配引擎、接口协议零改动 |
| D7 | 动作配置独立 `actions.yaml`，指令按动作 id 引用；`type` 之后的字段由 Handler 自定义并自行校验 | 动作可复用；指令管"听懂"、动作管"执行"；引擎对动作字段结构零假设（不透明透传） |
| D8 | ASR 用 Vosk（`com.alphacephei:vosk:0.3.45`，Maven Central，JNA）+ vosk-model-small-cn-0.22（44MB） | 离线、纯 Maven 依赖、官方提供 linux x86_64/aarch64 等 native（国产化迁移易）；实测识别 8/10、2 处同音错字，靠正则放宽与候选兜底（见第 9 节）。**注意：必须设置 `jna.encoding=UTF-8`，否则中文识别结果乱码** |

### 3.3 重要环境约束（必须写进部署说明）

浏览器的 `getUserMedia`（麦克风）**仅在安全上下文可用**：`localhost` 或 HTTPS。局域网内用 `http://192.168.x.x` 访问时浏览器会禁用麦克风。可选解法：

- 本机使用：直接访问 `localhost`（默认推荐，零配置）；
- 局域网多设备使用：后端配置自签证书启用 HTTPS（部署文档给出脚本）。

## 4. 功能需求

> 编号规则：FR-xx。每条含验收标准，作为一期验收依据。

### FR-1 语音输入（前端）

- 页面提供麦克风按钮，**点击开始录音**，录音中显示音量指示与"停止"按钮；
- 前端静音检测：连续静音约 1 秒（时长由后端配置下发，默认 1000ms）**自动结束录音**并立即上传识别；
- 手动点击"停止"随时可结束（兜底）；最长录音 60 秒强制结束；
- 采集规格：16kHz、16bit、单声道，前端编码为 WAV 上传；
- 浏览器授权被拒/无麦克风时给出明确提示。

**验收**：点击后说话，停顿约 1 秒自动上传；点击停止立即上传；授权拒绝时有友好错误提示。

### FR-2 指令一体化接口（后端）

- `POST /api/voice/command`，请求体为 WAV 音频；
- 一次调用完成：ASR → 归一化 → 匹配 → 执行动作（经 ActionHandler 工厂分发）→ 返回完整链路结果；
- 响应字段：

```json
{
  "asr_text": "空调温度调到二十六度",
  "normalized_text": "空调温度调到26度",
  "match": {
    "command_id": "ac_temp",
    "name": "空调温度调节",
    "by": "rule | keyword",
    "score": 1.0,
    "slots": { "value": "26", "mode": "set" }
  },
  "candidates": [ { "command_id": "ac_on", "name": "打开空调", "score": 0.5 } ],
  "action": { "ok": true, "action_id": "ha_climate_set_temp", "handler": "http", "status": 200, "elapsed_ms": 120, "summary": "{...响应摘要...}" },
  "elapsed_ms": 890
}
```

- `match` 为 null 表示未命中（此时 `candidates` 返回 Top3 供前端展示）；
- ASR 空文本/纯噪声：`match` 为 null、`candidates` 为空数组，前端提示"未识别到语音"；
- 动作执行失败不掩盖识别结果：失败信息完整带回前端。

**验收**：一条 3 秒语音从上传到收到完整响应，端到端 < 2 秒（普通 PC）。

### FR-3 文本归一化（后端）

匹配前统一处理，顺序执行：

1. 去所有空白（Vosk 输出为空格分词，实测）；
2. 全角转半角；
3. 去标点与句尾语气词（啊、呀、哦、呢、吧、嘛）——当前 Vosk 小模型无标点输出，此步为防御性保留；
4. 中文数字转阿拉伯数字，支持一～一百（例："二十六"→26、"一百零五"→105）——**必做**：Vosk 无 ITN，ASR 输出数字保持中文（实测），此步是数字指令可用的前提。

**验收**："开 空调 啊"归一化为"开空调"；"温度调到二十六度"归一化后含"26"。

### FR-4 意图匹配引擎（后端，核心）

两级流水线，任一级命中即停止。

**第一级：规则槽位匹配（参数指令专用）**

- 按指令在配置文件中的顺序（即优先级）逐条尝试其 `patterns` 正则；
- 命中即停止，通过命名捕获组与固定 `slots` 映射提取参数；
- 典型参数：`value`（数字）、`mode`（set/up/down）、`step`（幅度，默认 1）；
- 同一指令可配多条规则区分语义方向（见第 5 节示例）；
- **参数指令不参与第二级匹配**（保证"高一点/调低"零互串）。

**第二级：关键词权重匹配（无参数指令）**

- 仅对配置了 `keywords` 的指令生效；
- 关键词命中 = 归一化文本**包含**该关键词（每词最多计一次）；
- 指令得分 = Σ命中关键词权重 ÷ Σ该指令全部关键词权重，封顶 1.0；
- 取全部指令中的最高分：≥ 阈值（默认 0.70，`settings.yaml` 可配）即命中；同分取配置顺序靠前；
- 未达阈值视为未命中，返回 Top3 候选（带得分，前端仅展示）；
- 示例：`ac_on` 配置 `keywords: {开: 1, 空调: 1}`，则"开空调"得分 1.0 命中，"空调"得分 0.5 不命中，"关闭空调"得分 0.5 不命中。

**启动校验（配置加载时，不通过则拒绝加载）**

- `keywords` 与 `patterns` 必须且只能配其一；`keywords` 权重必须为正数；
- `patterns` 正则语法错误 → 报错并指出指令 id 与行号；
- 指令 id / 动作 id 重复 → 报错；
- 指令引用的动作 id 不存在、动作 `type` 无对应已注册 Handler → 报错（详见 FR-5）；
- 动作中的 `${槽位}` 占位符，必须能被引用它的指令的全部规则（命名捕获组 ∪ `slots` 键的并集）覆盖。

**验收（对应用户原始诉求）**：
- "打开空调 / 开空调 / 空调开启 / 帮我把空调打开" → 均命中 `ac_on`（关键词路径）；
- "关闭空调" → 命中 `ac_off`，不串 `ac_on`；
- "温度调到 26 度" → `value=26, mode=set`；
- "温度高一点 / 调高一点" → `mode=up, step=1`；"温度调低" → `mode=down, step=1`；
- 以上参数指令之间**零互相误命中**。

### FR-5 动作执行器（后端，工厂模式 ActionHandler）

**架构**：

```
ActionHandler（接口）—— 动作配置结构由各 Handler 自治
 ├─ String type()                          // 动作类型标识，对应 actions[].type
 ├─ ValidationResult validate(ActionDef)  // 校验本类型自有字段（如 url 合法性）
 └─ ActionResult execute(ActionDef, slots, ctx)

ActionHandlerFactory
 └─ type → Handler 注册表；Spring 容器自动收集所有实现类完成注册
```

- 动作定义独立存放于 `config/actions.yaml`，指令以 `action: <动作id>` 引用，同一动作可被多条指令复用；
- **`type` 之后的动作字段完全由对应 Handler 自行定义、解析、校验与执行**，引擎不做任何结构假设，作为不透明配置整体透传；
- 平台级约定仅两条，对所有 Handler 生效：
  1. `type` 分发：工厂按动作定义的 type 路由到 Handler；
  2. `${槽位名}` 占位符：引擎在分发前对动作配置做通用递归字符串替换（当前未提供的占位符替换为空字符串），Handler 拿到已替换配置 + 原始 slots（Handler 也可不用占位符，直接读取 slots 自行组装）；
- **一期唯一内置实现：`HttpActionHandler`（type = http）**：
  - 字段：`method` / `url` / `headers` / `body`，占位符可出现在任意字段任意位置；
  - 默认超时 10 秒（可配），超时或连接失败返回明确错误，**不自动重试**；
  - 响应体只保留摘要（前 500 字符）用于前端展示与日志；
- **扩展约定**：新增动作类型 = 新增一个 Handler 实现类（如二期 `local_command`、`keystroke`），引擎、工厂、接口协议零改动。

**验收**：
- 温度指令的 26 成功替换进请求体发出（可用 httpbin 类服务验证）；
- 同一动作被两条指令引用，均能正确执行；
- 配置未注册的 `type` 报错并指出动作 id；指令引用不存在的动作 id 报错并指出指令 id。

### FR-6 配置与热加载（后端）

- 配置全部手改 YAML（三个文件见第 5 节），一期不做管理界面；
- 文件监听（轮询 mtime）发现变化 ≤3 秒热加载，改动即时生效；
- 加载校验不通过时：保留上一份有效配置继续运行，日志输出错误详情（含文件名与行号）；
- 手改 `settings.yaml` 后阈值、静音时长等参数同样热加载生效。

**验收**：新增一条指令后 ≤3 秒内语音即可命中；写坏正则时系统不崩、保留旧配置并输出错误日志；改阈值后下一次匹配即生效。

## 5. 配置文件设计

文件：`config/commands.yaml`（指令）+ `config/actions.yaml`（动作）+ `config/settings.yaml`（系统参数）。**指令与动作解耦**：指令只描述"怎么听懂"，动作只描述"怎么执行"，指令通过动作 id 引用，同一动作可复用。

```yaml
# config/settings.yaml
settings:
  match:
    keyword_threshold: 0.70    # 关键词权重命中阈值
  audio:
    silence_ms: 1000           # 前端静音自动停时长（GET /api/settings 下发给前端）
  action:
    http_timeout_ms: 10000     # http Handler 专属参数
```

```yaml
# config/actions.yaml —— 动作定义；type 之后的字段由对应 Handler 自定义
actions:
  - id: ha_climate_on                     # 动作唯一 id，供指令引用
    name: 打开空调                         # 展示名（可选）
    type: http                            # 动作类型 → 工厂分发到 HttpActionHandler
    method: POST                          # ↓ 以下均为 http Handler 的自有字段
    url: http://192.168.1.10:8123/api/services/climate/turn_on
    headers:
      Authorization: "Bearer xxx"
    body: '{"entity_id": "climate.ac"}'

  - id: ha_climate_off
    name: 关闭空调
    type: http
    method: POST
    url: http://192.168.1.10:8123/api/services/climate/turn_off
    body: '{"entity_id": "climate.ac"}'

  - id: ha_climate_set_temp
    name: 设置空调温度
    type: http
    method: POST
    url: http://192.168.1.10:8123/api/services/climate/set_temperature
    body: '{"entity_id":"climate.ac","temperature":"${value}","mode":"${mode}","step":"${step}"}'
```

```yaml
# config/commands.yaml —— 指令定义，动作以 id 引用
commands:
  - id: ac_on                          # 唯一 id
    name: 打开空调                      # 展示名
    enabled: true
    action: ha_climate_on               # 引用 actions.yaml 中的动作 id
    keywords:                          # 关键词权重（无参数指令）
      开: 1
      空调: 1

  - id: ac_off
    name: 关闭空调
    enabled: true
    action: ha_climate_off
    keywords:
      关: 1
      空调: 1

  - id: ac_temp                        # 参数类指令：必须且只能走 patterns
    name: 空调温度调节
    enabled: true
    action: ha_climate_set_temp
    patterns:                          # Java 正则语法：命名组为 (?<name>...)
      - regex: '温度.*?(设|调)到?(?<value>\d+)\s*度'
        slots: { mode: set }
      - regex: '(调高|升高|高一点|太?冷)'
        slots: { mode: up, step: 1 }
      - regex: '(调低|降低|低一点|太?热)'
        slots: { mode: down, step: 1 }
```

> 示例正则按理想 ASR 输出编写。小模型存在同音错字（如"设置到"→"设知道"，见第 9 节），实机调参时可适当放宽。

指令字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一，稳定标识 |
| `name` | 是 | 展示名 |
| `enabled` | 否 | 默认 true，停用后不参与匹配 |
| `action` | 是 | 引用的动作 id（定义在 actions.yaml） |
| `keywords` | 二选一 | 关键词权重表（无参数指令），与 `patterns` 必须且只能配其一 |
| `patterns` | 二选一 | 规则列表（参数指令），按序匹配；`regex` 用 Java 语法命名组 `(?<name>...)`，`slots` 为固定键值 |

动作字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 动作唯一 id，被指令引用 |
| `name` | 否 | 展示名 |
| `type` | 是 | 动作类型，工厂据此分发到对应 ActionHandler；一期仅 `http` |
| （其余字段） | 由 Handler 决定 | `type` 之后完全由 Handler 自行定义与校验，引擎不解析、透传执行；`${槽位名}` 占位符为平台级通用约定 |

## 7. 非功能需求

| 类别 | 指标 |
|---|---|
| 端到端延迟 | 点击停止 → 前端收到完整结果 < 2s（普通 PC、5 秒内语音） |
| ASR 性能 | 模型加载 < 1s（实测 ~0.6s）；稳态 RTF ≤ 0.2（实测 0.06~0.16）；启动后预热一次解码 |
| 空闲资源 | 后端空闲 CPU ≈ 0%；进程内存 < 500MB（小模型实测） |
| 离线性 | 断网环境下除 HTTP 动作本身外全部功能可用 |
| 跨平台 | 后端 Windows / Linux（x64 与 aarch64）可运行；Vosk 由官方提供对应平台 native 包 |
| 部署形态 | 单 jar（内含前端产物）+ `config/` + `models/`（约 44MB）三个部分 |
| 音频传输 | 16kHz/16bit 单声道 ≈ 32KB/s，10 秒语音约 320KB，无压缩压力 |

## 9. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 小模型同音错字（实测 2/10 句："设置到"→"设知道"、"调低"→"调的"、数字后多字） | 高 | 参数指令正则按实机输出适当放宽；未命中走 Top3 候选兜底；不满足精度时升级大模型（实测 10/10、同音错字 0，代价约 2GB/加载 22s） |
| 关键词误命中（子串巧合、语义相反） | 中 | 覆盖率式得分 + 阈值（默认 0.70）+ 参数指令只走规则；上线初期用真实语音按附录 A 用例回归并调阈值 |
| 中文数字口语变体识别偏差 | 中 | FR-3 归一化（必做）覆盖一～一百常见说法，超出范围走候选确认 |
| HTTP 目标不可达/超时 | 低 | 明确超时与错误提示，不自动重试（目标系统幂等性未知） |
| 浏览器麦克风安全上下文限制 | 低 | localhost 默认可用；局域网部署给自签 HTTPS 方案（见 3.3） |

## 10. 演进路线

**二期候选（按优先级）**

1. ASR 升级大模型 vosk-model-cn-0.22（识别 10/10、同音错字 0；代价：模型约 2GB、加载 ~22s、内存 ≥8GB 部署机）；
2. 匹配测试面板：输入文本免语音查看命中与得分，调阈值利器；
3. 未命中候选一键执行；
4. 指令/动作管理页与系统设置页（增删改查写回 YAML）；
5. 执行历史：全链路留痕（内存环形队列 + 按天滚动日志）；
6. 会话窗口：点击一次后保持 N 秒连续多指令，超时或"退出"结束；
7. 语音唤醒词、TTS 播报（"好的，温度调到 26 度"）；
8. 拼音级容错匹配、档位槽位（最大/最小/自动）。

**三期方向**

- 嵌入式部署（树莓派等，后端直连麦克风阵列）；
- 指令"设备 × 动作"组合建模；
- 动作类型扩展：新增 ActionHandler 实现（本地命令/脚本、模拟按键、系统操作），配置改 `type` 即用，引擎零改动。
